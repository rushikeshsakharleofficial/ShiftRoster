## Critical Issues (Fix Immediately)
### ISSUE-001: Login Lockout Timezone Crash
- Severity: **CRITICAL**
- Location: `backend/routes/auth.py:64`
- Description: When multiple failed login attempts trigger the lockout mechanism, the backend crashes with a `TypeError` because it compares a timezone-aware datetime with a timezone-naive one.
- Steps to Reproduce:
  1. Send multiple (approx 10+) invalid login requests to `/api/auth/login`.
  2. Observe `500 Internal Server Error` instead of `401` or `429`.
- Expected: Should return a 401 with lockout message or 429 Too Many Requests.
- Actual: 500 Internal Server Error.
- Error Log: `TypeError: can't compare offset-naive and offset-aware datetimes`

## Security Findings
### SEC-001: Missing Security Headers
- Severity: **MEDIUM**
- Location: Nginx / Backend
- Description: Headers like `X-Frame-Options`, `Content-Security-Policy`, and `Strict-Transport-Security` are missing from responses.

### SEC-002: Lack of Rate Limiting
- Severity: **MEDIUM**
- Location: `/api/auth/login`
- Description: No standard rate limiting (like slow-down or temporary block) exists before the (currently broken) database-level lockout kicks in.

## Recommendations
1. **Fix Timezone Issue**: In `backend/routes/auth.py`, ensure all datetime comparisons use `timezone.utc`.
2. **Add Security Headers**: Update `nginx/entrypoint.sh` or config to include standard security headers.
3. **Implement Rate Limiting**: Use a middleware (e.g., `slowapi`) or Nginx `limit_req` to protect the login endpoint.
4. **Fix UI Selectors**: Ensure logout and other critical actions have clear `data-testid` attributes for better testability.
